# ── 제목: 유형: 내용 (영문 기준 50자 이내, 끝에 마침표 금지) ──────────

# ── 빈 행 (지우지 마세요) ─────────────────────────────────────────

# ── 본문: 무엇을, 왜 바꿨는지 (어떻게는 코드가 설명함) ─────────────
# - 변경 내용 1
# - 변경 내용 2

# ─────────────────────────────────────────────────────────────────
# 커밋 유형
#   Feat            새로운 기능 추가
#   Fix             버그 수정
#   Docs            문서 수정
#   Style           코드 포맷팅, 세미콜론 누락 등 코드 자체 변경이 없는 경우
#   Refactor        코드 리팩토링
#   Test            테스트 코드 추가 및 리팩토링
#   Chore           패키지 매니저 수정, 그 외 기타 수정 (예: .gitignore)
#   Design          CSS 등 사용자 UI 디자인 변경
#   Comment         필요한 주석 추가 및 변경
#   Rename          파일 또는 폴더명 수정, 이동만 한 경우
#   Remove          파일 삭제만 수행한 경우
#   !BREAKING CHANGE  API의 커다란 변경
#   !HOTFIX         급하게 치명적인 버그를 고쳐야 하는 경우
#
# 규칙
#   - 한 커밋에는 한 가지 문제만 담을 것
#   - 유형은 영어 대문자로 시작, 제목과 본문은 한글로 작성
#   - 제목과 본문 사이는 빈 행으로 분리
#   - 항목이 여러 개면 글머리 기호(-)로 나열
#
# 예시
#   Feat: S0 프로세스 바 컴포넌트 추가
#
#   - 완료·현재·미도달 3가지 상태를 시각적으로 구분
#   - 전 단계에서 공통으로 쓰기 위해 components/ 하위에 배치
# ─────────────────────────────────────────────────────────────────
